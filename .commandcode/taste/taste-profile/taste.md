# Taste Profile
- User communicates in Bahasa Indonesia; respond, write plans, and produce app UI text in Indonesian. Confidence: 1.0
- Prefers a plan-first workflow: draft a written plan, wait for user approval, then execute the approved plan on explicit instruction (e.g., "eksekusi rencana ... untuk di implementasikan", "buat saja dulu untuk fitur laporan"). Confidence: 0.9
- Expects the existing project structure (models, services, state management, screens, DB schema) to be analyzed and documented before any code change. Confidence: 0.8
- Prefers phased delivery by priority: core features first, defer optional extras (e.g., export) rather than implementing everything at once. Confidence: 0.7
- Prefers compact layouts where all content (e.g., dashboard menu grid) fits on screen without scrolling. Confidence: 0.6
- Follows the project's existing architecture and state management (Provider/Bloc/etc.) instead of introducing new patterns. Confidence: 0.8
- Avoids altering existing database schema or working features (e.g., Kasir, Produk) unless strictly necessary; when requesting new features, explicitly asks that existing functionality not be changed or broken ("tanpa mengubah atau merusak fitur transaksi yang sudah ada"). Confidence: 0.8
- Reports UI/runtime errors by attaching screenshots of the problem plus a precise description of expected vs. actual behavior (e.g., a screenshot of a normal-looking Daftar Transaksi with "setelah di klik masih tidak muncul detail transaksinya") and expects the fix to target the reported symptom. Confidence: 0.85
- Prefers the app to have distinct user roles with role-gated menus/features: admin sees Produk, Laporan, and Manajemen Kasir but NOT the Kasir/POS feature; kasir sees only Kasir (payment) and Laporan. Confidence: 0.8
- Expects new features to be reachable/verified across all relevant roles — explicitly asks follow-up verification questions like "Apakah sudah ditambahkan di semua role?" and expects the answer to trace each role's access path (menu, dialog, navigation) to the feature, not just one entry point. Confidence: 0.6
- Reports a problem first and expects diagnosis driven by investigation of the running system (checking ports, services, logs, DB) before touching code — e.g., a login "Failed to fetch" that turned out to be the backend not running, not a code bug. Re-reports the same symptom tersely ("Masih tidak muncul") without new details even after being given fix steps; expects the agent to re-verify the environment (e.g., process start times) and keep digging to the actual code-level root cause rather than re-asking or repeating instructions. Re-confirmed with the new report "Tidak bisa login admin dan karyawan" (no error message, platform, or screenshot given); after the agent asked clarifying questions, no answers followed and the agent proceeded on best assumptions and continued investigating. Confidence: 0.9
- Prefers secondary/utility menus (e.g., Laporan, Manajemen Karyawan) to be moved from the central dashboard grid into the AppBar's top-right as icon buttons, grouped near the Logout action, rather than kept as large menu cards in the body grid. Confidence: 0.7
- Prefers clicking a list item to open a dedicated full-screen detail page (Scaffold + AppBar with back navigation) rather than a modal bottom sheet for *viewing* records — e.g., clicking a transaction in Laporan's Daftar Transaksi must navigate to a Detail Transaksi page showing nomor, tanggal, waktu, and metode pembayaran. Confidence: 0.7
- For *editing* a record, prefers an in-place modal Bottom Sheet (not navigation) with a pre-filled form — e.g., tapping a product card must NOT change page; it opens a "Update Produk" bottom sheet from the bottom of the screen pre-filled with the selected product's data. Confidence: 0.9
- Dislikes duplicate UI controls for the same action: explicitly asked to remove the redundant "Keluar" menu-grid buttons on both admin and kasir dashboards because an identical logout button already existed in the top-right AppBar — the AppBar action is the canonical place to keep, duplicates in body/menu cards should be removed. Confidence: 0.9
